# Chapter 08: 工具调用体系完善

## 阶段记录

### 2024-01-XX - 任务启动
**用户需求**：
- 用 Superpowers 模式完善数据平台 agent 的工具调用体系
- 核心功能：参数校验、权限控制、审计留痕、超时重试、人工审批（二次确认）
- 技术栈：Spring Boot + Spring AI 1.0.0 + networknt/json-schema-validator
- 不用 graph 重构，在当前架构继续

**当前步骤**：查询 Spring AI 1.0.0 文档，确认 ToolCallback、ReactAgent 等 API

### Brainstorm 阶段完成（2024-01-XX）
**我说的关键原话**：
- "这个项目用的就是 springai1.0.0"
- 要求查询 Context7 文档确认 API

**产出**：
- 技术设计文档：`dev-notes/ch08-design.md`
- 确认 Spring AI 1.0.0 核心 API：
  - `ToolCallback` 接口（getToolDefinition/getToolMetadata/call）
  - `ToolContext` 传递上下文（userId、roles）
  - `ToolCallbacks.from()` 自动转换 @Tool 方法
  - `ToolCallingManager` 执行工具调用

**架构设计**：
- 装饰器链模式：Audit → Permission → Confirmation → Validation → TimeoutRetry → 原始工具
- 每个装饰器单一职责，通过 BeanPostProcessor 自动装配
- 审计在最外层捕获所有事件（包括拦截）
- 二次确认用 JWT token 绑定工具名+参数哈希

**拒绝/纠偏**：无

**翻车与返工**：无

### 计划阶段完成（2024-01-XX）
**我的产出**：
- 完整实施计划：`.claude/plans/ch08-implementation-plan.md`

**关键发现（探索阶段）**：
1. **现有代码结构**：
   - 工具使用 Spring AI `@Tool` 注解（JobTool、DataSourceTool）
   - 通过 `ToolCallbacks.from()` → `ObservableToolCallback` 包装
   - 已有 ConfirmationService（JWT token 防重放）
   - ValidationDecorator 存在但用硬编码 switch-case（不通用）
   - 审计仅打日志，无持久化
   
2. **架构问题**：
   - 装饰器未形成统一链，各自独立
   - `@RequireConfirmation` 注解未实际生效
   - 参数校验不基于 JSON Schema
   - 缺少权限拦截和超时重试

**设计方案核心**：
- **不引入新抽象**，在 `ObservableToolCallback.call()` 中顺序执行 Interceptor
- **拦截器顺序**：Audit → Permission → Confirmation → Validation → TimeoutRetry → delegate.call()
- **上下文传递**：`ToolExecutionContext` 携带 userId、roles、conversationId、confirmationToken
- **审计持久化**：新增 `tool_audit_logs` 表，记录所有状态（包括拦截事件）
- **权限/确认规则**：用 YAML 配置（`tool.governance.*`）

**实施步骤（6个阶段）**：
1. 基础设施（DB、配置、异常类）
2. 拦截器实现（5个 Interceptor）
3. 集成（重构 ObservableToolCallback）
4. 配置与异常处理（YAML + SSE events）
5. 测试验证
6. 文档更新

**风险缓解**：
- JSON Schema 不可用 → 退化为基础 null 检查
- `@RequireConfirmation` 无法传递 → 改用配置文件匹配工具名
- 拦截器性能 → 审计异步化
