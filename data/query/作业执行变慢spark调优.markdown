# 文档二：Spark/Hive 参数调优知识库 - 作业变慢篇

> **文档定位**：用于沉淀 Spark/Hive 参数调优场景下导致**作业能成功跑完，但是耗时很长、执行缓慢**的典型现象及可调参数，供检索和问答路由参考。

---

## 1. Shuffle spill to disk（溢写磁盘）
### 作业能跑完但非常慢，查看日志发现大量 `spill to disk` 记录，shuffle 阶段拖得很久，机器 IO 负载高。
*   **可调参数 / 方向**：
    *   调大 shuffle buffer（如 `spark.shuffle.file.buffer`）。
    *   调大 reducer 拉取数据的上限。
    *   开启 AQE 优化。

---

## 2. 数据倾斜（单点长尾）
### 作业能够跑完，但整体耗时很长。查看监控发现，绝大部分 task 几秒钟就跑完了，但只有 1~2 个 task 跑了几十分钟，严重拖慢了整个作业进度。
*   **可调参数 / 方向**：
    *   开启 AQE 倾斜优化功能（自动拆分大 task）。
    *   调整 skew join 相关参数。

---

## 3. 小文件太多导致读取/调度慢
###  作业读取阶段非常慢，或者 task 数量巨多，每个 task 处理的数据量极少，导致 task 调度和启动开销远大于计算开销。
*   **可调参数 / 方向**：
    *   开启小文件合并（如 `spark.sql.mergeSmallFiles.enabled` 等）。
    *   控制动态分区输出文件数。
    *   调整输入合并参数。

---

## 4. 并行度不合理
### 分区太少或太多。并行度太低会导致单 task 处理数据压力极大（易慢甚至转OOM）；并行度太高会导致 task 调度开销、shuffle 开销爆炸。
*   **可调参数 / 方向**：
    *   调整 shuffle 默认分区数：`spark.sql.shuffle.partitions`
    *   开启 AQE 自动调整 shuffle 分区（推荐）。

---

## 5. 网络传输慢、序列化格式不合理
### shuffle 阶段数据拉取缓慢，网络带宽打满。
*   **可调参数 / 方向**：
    *   开启 shuffle 压缩。
    *   更换更高效的序列化器：`spark.serializer`（如 Kryo）。

---

## 6. 大量 sort、distinct 操作
### SQL 中包含大量全局排序或去重逻辑，导致排序开销极高，作业变慢。
*   **可调参数 / 方向**：
    *   调整排序相关阈值。
    *   开启 AQE 自动优化。
## 7. 现象：作业提交成功，长久未执行 / 一直 Pending
### 7.1 ：申请资源过大，长时间拿不到容器排队，作业状态 pending，日志出现 `Waiting for container`。资源池明明有资源，但很难满足该作业申请的超大规格。
*   **可调参数 / 方向**：
    *   调小 executor 内存。
    *   调小 executor 核数。
    *   拆分资源规格。

### 7.2 ：动态资源分配配置不合理，：开启动态资源分配后，获取 executor 缓慢，导致作业长时间等待。
*   **可调参数 / 方向**：
    *   调整 `spark.dynamicAllocation.*` 系列参数。
    *   调整 `minExecutors` / `maxExecutors`、申请等待超时时间。

### 7.3 边界声明：绝大多数 Pending，参数调优救不了
以下情况**不要放入调参知识库**，需直接回复排查资源与调度：
*   资源池整体容量打满，集群没有空闲资源（只能等别的作业释放资源）。
*   调度依赖还没就绪，例如上游分区没产出。
*   队列 / 资源池配额、优先级限制、租户配额限流。
*   YARN / K8s 调度策略、标签亲和限制。
