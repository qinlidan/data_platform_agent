## 1. 平台概述

### 1.1 平台是什么

本平台是一站式数据研发治理平台，对标阿里云 DataWorks，支持**数据接入、数据开发、任务调度、数据质量监控、元数据血缘、数据资产检索、告警**，统一离线/实时数据生产的工作台。

平台目标：替代零散脚本、本地 SQL、crontab 定时脚本，统一管理数据任务，保障数据生产可追溯、可运维、可管控。

### 1.2 适合哪些用户

- **数据开发工程师**：写 SQL、编排任务、调度跑批
- **数仓工程师**：建设分层数仓、管理表、梳理血缘
- **数据分析**：即席查询、查看表资产、查看指标
- **平台运维**：查看任务失败、处理告警、资源管理

### 1.3 平台能做什么（一句话问答摘要，知识库优先命中）

- 管理 MySQL / Kafka / Hive / ClickHouse / Doris 等数据源；
- 在线编写 SparkSQL、HiveSQL、FlinkSQL、Shell、Python 脚本；
- 通过拖拽画布编排 DAG，配置任务上下游依赖，自动定时调度；
- 查看任务运行日志、重跑、补历史数据、终止实例；
- 自动解析 SQL，生成表血缘、字段血缘，做影响分析；
- 配置数据质量规则，校验空值、行数、值域，脏数据可阻断下游；
- 检索数据资产表、查看表 DDL、分区、热度、负责人；
- 任务失败、质量异常自动发送告警。

### 1.4 平台不能做什么

不直接提供 BI 报表可视化；不替代底层计算引擎（Spark / Flink）；不直接做数据挖掘算法训练。

## 2. 核心术语词典（问答高频，用户经常问）

| 名词            | 解释                                                                                    |
| --------------- | --------------------------------------------------------------------------------------- |
| 项目 / 工作空间 | 资源、任务、表权限的隔离单元，不同业务域分开，项目之间默认隔离                          |
| 节点            | DAG 画布里面单个执行单元，比如 SQL 节点、同步节点、质量检查节点                         |
| 工作流          | 一组有依赖关系的节点组成的 DAG，一起调度运行                                            |
| 实例            | 工作流 / 节点**一次调度运行记录**，按调度日期生成，状态：等待、运行中、成功、失败、终止 |
| DAG             | 有向无环图，描述任务上下游依赖关系，A 跑完 B 才可以跑                                   |
| 补数据          | 对历史日期重新触发调度运行，用于修复历史数据                                            |
| 调度周期        | 日调度、小时调度、分钟调度，由 cron 表达式控制                                          |
| 血缘            | 表和表、字段和字段之间的数据流向关系，用来判断改表影响哪些下游                          |
| ODS             | 原始数据层，源数据原样同步，不清洗                                                      |
| DWD             | 明细层，清洗、去重、标准化后的明细数据                                                  |
| DWS             | 汇总层，按业务维度聚合                                                                  |
| ADS             | 应用层，指标宽表，供报表、API 使用                                                      |
| 数据质量规则    | 校验数据是否合格的规则，空值率、行数波动、唯一值校验等                                  |
| 阻断策略        | 质量校验失败后，是否阻止下游任务继续执行                                                |
| 元数据          | 表名、字段、类型、注释、分区、存储大小、行数等表信息                                    |

## 3. 平台整体使用流程（标准使用链路）

> 标准流程，用户上手主链路：

1. 管理员创建【项目】，添加成员，分配角色权限；
2. 在项目内注册【数据源】，连通测试；
3. 进入【数据开发】模块：新建工作流 → 添加节点（SQL / 同步节点）→ 编写 SQL / 脚本；
4. 画布连线配置上下游依赖（DAG），配置调度 cron、调度参数；
5. 保存、提交版本，支持版本对比、回滚；
6. 【调试运行】：手动触发单次调试，查看日志验证结果；
7. 提交调度：平台按照定时规则自动生成实例、调度执行；
8. 在【运维中心】查看实例状态，失败可重跑、查看日志、补数据；
9. 自动采集元数据、解析 SQL 生成血缘，在【数据地图】查看资产和血缘；
10. 可选：绑定【数据质量规则】，配置校验逻辑和告警；
11. 异常时在【告警中心】接收消息。

## 4. 各模块操作指南

### 4.1 项目与权限模块

#### 用途

用来做业务隔离、成员权限管控。

#### 角色说明

- **项目管理员**：增删成员、管理资源组、修改项目配置
- **开发**：新建、编辑、提交任务、调试、重跑实例
- **运维**：查看实例、重跑、终止实例，不能编辑任务
- **查看者**：只读，只能查看任务、表资产，无法执行操作

#### 常见操作

1. 切换项目：平台首页下拉选择项目；
2. 申请权限：没有项目权限，联系项目管理员添加；
3. 权限范围：项目内任务、数据源、表资产权限绑定项目。

### 4.2 数据源管理模块

#### 用途

统一登记所有要使用的数据库、消息队列，供开发节点读取写入。

#### 支持数据源

MySQL、PostgreSQL、ClickHouse、Doris、Hive、Kafka、HDFS。

#### 操作步骤

1. 进入【数据源管理】→ 新增数据源；
2. 选择数据源类型，填写地址、端口、账号密码；
3. 点击【连通性测试】，测试通过后保存；
4. 数据源保存后，开发节点里就可以选择该数据源执行 SQL。

> **注意**：密码加密存储，页面不展示明文密码。

### 4.3 数据开发模块（用户最常用）

#### 用途

在线写 SQL、编排任务依赖，开发离线/实时任务。

#### 页面组成

- **资源树**：保存所有工作流、节点脚本，支持文件夹分类；
- **DAG 画布**：拖拽节点、连线配置依赖；
- **SQL 编辑器**：语法高亮、格式化、预检查、预览数据；
- **配置面板**：调度参数、节点数据源、资源组、失败重试配置；
- **版本面板**：提交版本、版本对比、一键回滚。

#### 新建 SQL 任务步骤

1. 在资源树新建工作流；
2. 从左侧组件拖拽【SQL 节点】到画布；
3. 选中节点，右侧选择数据源（Hive / Spark / ClickHouse 等）；
4. 在编辑器输入 SQL，支持内置调度变量：`${bizdate}`、`${hour}`；
5. 配置调度：cron 周期、失败重试次数、超时时间；
6. 【调试运行】：手动跑一次，看执行日志、预览结果；
7. 调试没问题，提交版本，开启调度。

#### 版本管理操作

每次提交生成版本快照；可以对比两个版本 SQL 差异；支持一键回滚到历史版本。

#### 节点类型说明

- **SQL 节点**：SparkSQL / HiveSQL / ClickHouseSQL
- **FlinkSQL 节点**：实时流任务
- **数据同步节点**：数据从源同步到目标（DataX 同步）
- **Shell / Python 节点**：执行脚本
- **数据质量节点**：单独执行质量校验逻辑

### 4.4 运维调度模块（运维中心）

#### 用途

查看所有调度实例、处理失败任务、补历史数据。

#### 核心操作

1. **实例列表**：按时间、工作流、状态筛选实例；
2. **查看日志**：点击实例查看运行日志，定位报错；
3. **重跑实例**：失败实例修复 SQL 后，选中重跑；
4. **终止实例**：正在运行的异常任务，可以终止；
5. **补数据**：选择工作流、选择一段历史时间范围，批量生成历史实例执行。

> **注意**：补数据会按 DAG 依赖顺序执行，避免数据依赖缺失；大量补数据需要评估资源。

#### 实例状态说明

- **等待**：依赖节点还未完成，等待上游成功；
- **运行中**：正在引擎上执行；
- **成功**：执行完成；
- **失败**：执行报错，需要排查日志；
- **终止**：人工停止任务。

### 4.5 数据地图（元数据 & 血缘模块）

#### 用途

查找表资产、看表详情、查看数据流向、评估改表影响。

#### 操作步骤

1. 进入数据地图，搜索表名 / 字段 / 业务标签；
2. 表详情页：查看 DDL、字段注释、分区信息、数据预览、访问热度、负责人；
3. 血缘图谱：打开表血缘，可以看到上游来源表、下游依赖任务、下游产出表；
4. 影响分析：查看“如果修改当前表，会影响哪些下游任务、哪些报表”。

> 血缘由平台自动解析 SQL 生成，不需要人工维护。

### 4.6 数据质量模块

#### 用途

给表加上校验规则，防止脏数据流入下游。

#### 支持规则

- **表级规则**：分区是否存在、产出行数波动（和昨日对比波动超过阈值告警）；
- **字段级规则**：空值率、唯一值占比、值域范围、正则匹配；
- **自定义 SQL 规则**：自己写校验 SQL 判断结果是否符合预期。

#### 执行时机

- **前置校验**：任务跑之前校验，不通过直接不启动任务；
- **后置校验**：任务跑完之后校验，失败可以选择【阻断下游】或者只告警不阻断。

### 4.7 告警中心

#### 用途

接收任务失败、超时、质量校验失败消息。

#### 操作

1. 在任务 / 质量规则上绑定告警接收人；
2. 支持告警渠道：企业微信、邮件、Webhook；
3. 告警消息包含：任务名称、实例时间、失败原因、日志链接。

## 5. 配套数仓分层规范（平台内统一规范，用户写 SQL 参考）

1. **ODS 原始层**：同步源数据，原样落地，不清洗；
2. **DWD 明细层**：清洗、去重、过滤脏数据，保留明细；
3. **DWS 汇总层**：按主题、维度聚合，日 / 小时汇总；
4. **ADS 应用层**：指标宽表，直接给报表、业务 API 使用。

> 平台建议表名带上层标识，例如 `ods_mysql_user`、`dwd_user_detail`。

## 6. 常见问题 FAQ（知识库高频问答，重点，用户最常问）

> 这一部分是问答核心，用户提问优先匹配这里。

**Q1：平台是做什么的？**

A：一站式数据研发平台，用来做数据接入、SQL 开发、定时调度、任务运维、数据血缘和数据质量监控，替代手工脚本跑数据。

**Q2：怎么新建一个定时跑的 SQL 任务？**

A：进入数据开发，新建工作流，拖拽 SQL 节点，选择数据源，编写 SQL，配置 cron 调度周期，调试运行，提交调度即可。

**Q3：任务失败了怎么排查？**

A：打开运维中心，找到对应失败实例，查看运行日志，根据日志报错修改 SQL 或者资源配置，修复后重跑。

**Q4：补数据是什么，什么时候用？**

A：补数据是重新跑历史日期的任务；适合修复历史脏数据、漏跑数据场景；在运维中心找到工作流，点击补数据，选择时间范围提交。

**Q5：血缘怎么生成？需要手动画吗？**

A：不需要手动维护；平台自动解析任务里面的 SQL，自动提取表、字段的上下游关系生成血缘。

**Q6：数据质量失败，怎么设置不让下游继续跑？**

A：编辑质量规则，把校验失败策略设置为【阻断下游】，校验不通过，下游节点不会启动。

**Q7：`${bizdate}` 是什么？**

A：平台内置调度变量，代表当前调度业务日期，格式 `yyyy-MM-dd`。

**Q8：可以同时跑离线 Spark 和实时 Flink 任务吗？**

A：支持，在开发面板选择对应类型节点即可。

**Q9：为什么我看不到某张表？**

A：两种情况：① 元数据采集任务还没采集到该表；② 当前账号没有这个项目 / 表的查看权限，联系管理员。

**Q10：调试运行和提交调度有什么区别？**

A：调试运行是手动一次性执行，只用来验证 SQL 是否正确，不会按周期自动跑；提交调度后，平台会按照 cron 周期自动生成实例定时执行。

**Q11：版本回滚怎么用？**

A：在任务版本列表，找到目标历史版本，点击回滚，任务会切换为该版本的脚本，建议回滚前先调试验证。

**Q12：任务依赖是什么意思？**

A：DAG 画布连线就是依赖，上游节点成功跑完，下游节点才会开始执行，保证数据顺序。
