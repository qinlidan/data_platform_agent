# 数据研发平台用户手册（知识库问答专用版）

## 平台概述与介绍

### 平台是什么？
本平台是一站式数据研发治理平台，对标阿里云 DataWorks。支持数据接入、数据开发、任务调度、数据质量监控、元数据血缘、数据资产检索、告警，统一离线/实时数据生产的工作台。目标是替代零散脚本、本地 SQL、crontab 定时脚本，保障数据生产可追溯、可运维、可管控。

### 适合哪些用户使用？
- **数据开发工程师**：写 SQL、编排任务、调度跑批
- **数仓工程师**：建设分层数仓、管理表、梳理血缘
- **数据分析**：即席查询、查看表资产、查看指标
- **平台运维**：查看任务失败、处理告警、资源管理

### 平台能做什么？
- 管理 MySQL / Kafka / Hive / ClickHouse / Doris 等数据源；
- 在线编写 SparkSQL、HiveSQL、FlinkSQL、Shell、Python 脚本；
- 通过拖拽画布编排 DAG，配置任务上下游依赖，自动定时调度；
- 查看任务运行日志、重跑、补历史数据、终止实例；
- 自动解析 SQL，生成表血缘、字段血缘，做影响分析；
- 配置数据质量规则，校验空值、行数、值域，脏数据可阻断下游；
- 检索数据资产表、查看表 DDL、分区、热度、负责人；
- 任务失败、质量异常自动发送告警。

### 平台不能做什么？
不直接提供 BI 报表可视化；不替代底层计算引擎（Spark / Flink）；不直接做数据挖掘算法训练。

## 核心术语词典（高频问答）

### 什么是项目/工作空间？
资源、任务、表权限的隔离单元，不同业务域分开，项目之间默认隔离。

### 什么是节点和工作流？
- **节点**：DAG 画布里面单个执行单元，比如 SQL 节点、同步节点、质量检查节点。
- **工作流**：一组有依赖关系的节点组成的 DAG，一起调度运行。

### 什么是实例？
工作流 / 节点一次调度运行记录，按调度日期生成。状态包括：等待、运行中、成功、失败、终止。

### 什么是 DAG？
有向无环图，描述任务上下游依赖关系，A 跑完 B 才可以跑。

### 什么是补数据和调度周期？
- **补数据**：对历史日期重新触发调度运行，用于修复历史数据。
- **调度周期**：日调度、小时调度、分钟调度，由 cron 表达式控制。

### 什么是血缘？
表和表、字段和字段之间的数据流向关系，用来判断改表影响哪些下游。

### ODS、DWD、DWS、ADS 分别代表什么？
- **ODS**：原始数据层，源数据原样同步，不清洗；
- **DWD**：明细层，清洗、去重、标准化后的明细数据；
- **DWS**：汇总层，按业务维度聚合；
- **ADS**：应用层，指标宽表，供报表、API 使用。

### 什么是数据质量规则和阻断策略？
- **数据质量规则**：校验数据是否合格的规则，如空值率、行数波动、唯一值校验等。
- **阻断策略**：质量校验失败后，是否阻止下游任务继续执行。

### 什么是元数据？
表名、字段、类型、注释、分区、存储大小、行数等表信息。

## 平台整体使用流程

### 平台的标准使用链路是什么？
1. 管理员创建【项目】，添加成员，分配角色权限；
2. 在项目内注册【数据源】，连通测试；
3. 进入【数据开发】模块：新建工作流 → 添加节点（SQL / 同步节点）→ 编写 SQL / 脚本；
4. 画布连线配置上下游依赖（DAG），配置调度 cron、调度参数；
5. 保存、提交版本，支持版本对比、回滚；
6. 【调试运行】：手动触发单次调试，查看日志验证结果；
7. 提交调度：平台按照定时规则自动生成实例、调度执行；
8. 在【运维中心】查看实例状态，失败可重跑、查看日志、补数据；
9. 自动采集元数据、解析 SQL 生成血缘，在【数据地图】查看资产和血缘；
10. 可选：绑定【数据质量规则】，配置校验逻辑和告警；
11. 异常时在【告警中心】接收消息。

### 项目与权限模块有什么用途？
用来做业务隔离、成员权限管控。项目内任务、数据源、表资产权限均绑定项目。

### 平台有哪些角色及对应的权限？

### 如何切换项目或申请权限？
- **切换项目**：平台首页下拉选择项目。
- **申请权限**：没有项目权限，联系项目管理员添加。

## 数据开发模块

### 数据开发模块有什么用途？
在线写 SQL、编排任务依赖，开发离线/实时任务。是用户最常用的模块。

### 数据开发页面由哪些部分组成？
- **资源树**：保存所有工作流、节点脚本，支持文件夹分类；
- **DAG 画布**：拖拽节点、连线配置依赖；
- **SQL 编辑器**：语法高亮、格式化、预检查、预览数据；
- **配置面板**：调度参数、节点数据源、资源组、失败重试配置；
- **版本面板**：提交版本、版本对比、一键回滚。

### 怎么新建一个定时跑的 SQL 任务？
1. 在资源树新建工作流；
2. 从左侧组件拖拽【SQL 节点】到画布；
3. 选中节点，右侧选择数据源（Hive / Spark / ClickHouse 等）；
4. 在编辑器输入 SQL，支持内置调度变量：`${bizdate}`、`${hour}`；
5. 配置调度：cron 周期、失败重试次数、超时时间；
6. 【调试运行】：手动跑一次，看执行日志、预览结果；
7. 调试没问题，提交版本，开启调度。

### 如何进行版本管理？
每次提交生成版本快照；可以对比两个版本 SQL 差异；支持一键回滚到历史版本。

### 平台支持哪些节点类型？
- **SQL 节点**：SparkSQL / HiveSQL / ClickHouseSQL
- **FlinkSQL 节点**：实时流任务
- **数据同步节点**：数据从源同步到目标（DataX 同步）
- **Shell / Python 节点**：执行脚本
- **数据质量节点**：单独执行质量校验逻辑

## 运维调度模块（运维中心）

### 运维调度模块有什么用途？
查看所有调度实例、处理失败任务、补历史数据。

### 运维中心的核心操作有哪些？
1. **实例列表**：按时间、工作流、状态筛选实例；
2. **查看日志**：点击实例查看运行日志，定位报错；
3. **重跑实例**：失败实例修复 SQL 后，选中重跑；
4. **终止实例**：正在运行的异常任务，可以终止；
5. **补数据**：选择工作流、选择一段历史时间范围，批量生成历史实例执行。

### 任务实例有哪些状态？
- **等待**：依赖节点还未完成，等待上游成功；
- **运行中**：正在引擎上执行；
- **成功**：执行完成；
- **失败**：执行报错，需要排查日志；
- **终止**：人工停止任务。

### 补数据需要注意什么？
补数据会按 DAG 依赖顺序执行，避免数据依赖缺失；大量补数据需要评估资源。

## 数据地图（元数据与血缘）

### 数据地图模块有什么用途？
查找表资产、看表详情、查看数据流向、评估改表影响。

### 如何查找表资产和查看表详情？
1. 进入数据地图，搜索表名 / 字段 / 业务标签；
2. 表详情页：查看 DDL、字段注释、分区信息、数据预览、访问热度、负责人。

### 血缘怎么生成？需要手动画吗？
不需要手动维护；平台自动解析任务里面的 SQL，自动提取表、字段的上下游关系生成血缘。

### 怎么做影响分析？
在血缘图谱中打开表血缘，可以看到上游来源表、下游依赖任务、下游产出表。查看“如果修改当前表，会影响哪些下游任务、哪些报表”。

## 数据质量模块

### 数据质量模块有什么用途？
给表加上校验规则，防止脏数据流入下游。

### 支持哪些数据质量规则？
- **表级规则**：分区是否存在、产出行数波动（和昨日对比波动超过阈值告警）；
- **字段级规则**：空值率、唯一值占比、值域范围、正则匹配；
- **自定义 SQL 规则**：自己写校验 SQL 判断结果是否符合预期。

### 数据质量校验的执行时机是什么？
- **前置校验**：任务跑之前校验，不通过直接不启动任务；
- **后置校验**：任务跑完之后校验，失败可以选择【阻断下游】或者只告警不阻断。

### 数据质量失败，怎么设置不让下游继续跑？
编辑质量规则，把校验失败策略设置为【阻断下游】，校验不通过，下游节点不会启动。

1. **ODS 原始层**：同步源数据，原样落地，不清洗；
2. **DWD 明细层**：清洗、去重、过滤脏数据，保留明细；

## 一、数据集成同步类 (DataX)

### Q1: 脏数据过多导致任务失败
- **报错关键字**：`Code:[DBUtilErrorCode-10]`, `脏数据`, `Dirty data`, `You have exceeded the limit of dirty records`
- **根本原因**：
  1. 源端与目标端**字段类型不匹配**（如源端 String 到目标端 Long 转换失败）。
  2. 存在**非法字符**（如目标库为 MySQL，遇到 Emoji 表情或 `\0` 字符）。
  3. 字段长度超出目标端建表限制。
- **解决方案**：
  1. **排查具体脏数据**：在同步任务日志中查找 `脏数据` 详情，定位具体失败的行和列。
  2. **配置类型转换**：在同步节点“字段映射”中，手动配置转换规则或使用 `TryCast` 函数。
  3. **清洗数据**：在同步前增加 SQL 节点，利用 `replace()` 或正则过滤非法字符。
  4. **调整脏数据阈值**：若少量脏数据可容忍，可在节点配置中调大 `dirtyDataLimit` 和 `dirtyDataPercentage`。

### Q2: 数据库连接失败 / 网络不通
- **报错关键字**：`Communications link failure`, `Connection refused`, `UnknownHostException`, `timeout`
- **根本原因**：
  1. 数据库白名单未放行 DataWorks 资源组 IP。
  2. 数据源配置的 JDBC URL、端口、账号密码错误。
  3. 网络环境不通（如资源组在公网，数据库在 VPC 内网）。
- **解决方案**：
  1. **检查白名单**：复制报错日志中提示的 DataWorks 资源组 IP，添加到数据库白名单。
  2. **检查连通性**：在 DataWorks“数据集成” -> “数据源”页面，点击对应数据源进行“连通性测试”。
  3. **专有网络**：VPC 环境需确保正确绑定 `VPC ID`、`交换机 ID` 和 `安全组`。

## 二、计算引擎类 (MaxCompute)

### Q3: 内存溢出 (OOM) / 资源不足
- **报错关键字**：`ODPS-0130071`, `Java heap space`, `Memory exceeded`, `Memory quota exceeded`
- **根本原因**：
  1. **数据倾斜**：某个 Key 数据量极大，导致分配到该 Key 的 Worker 内存撑爆。
  2. **大表关联未加过滤**：Join 超大表且未使用 MapJoin。
  3. 复杂 UDF 或死循环占用大量内存。
- **解决方案**：
  1. **解决数据倾斜**：检查 Join 键或 Group By 键是否有热点值（如 `null` 集中）。可通过 `distribute by rand()` 打散或过滤异常 Key。
  2. **开启 MapJoin**：大表 Join 小表时，显式添加 Hint：`/*+ MAPJOIN(b) */`。
  3. **调大资源参数**：在 SQL 头部添加 `set odps.sql.mapper.memory=4096;`（单位 MB）增大单节点内存。

### Q4: 权限不足 (No Permission)
- **报错关键字**：`ODPS-0420095`, `No permission`, `Access Denied`
- **根本原因**：执行账号没有对目标表、Schema 或 Project 的读/写权限。
- **解决方案**：
  1. **申请权限**：通过 DataWorks 数据地图或安全中心，申请目标表的 `Select` 或 `Update` 权限。
  2. **检查访问身份**：确认任务配置的“访问身份”（主账号、子账号或自定义 RAM 角色）是否具备权限。
  3. **跨项目授权**：跨 Project 访问需开通 `Package` 授权，并写全表名 `project_name.table_name`。

## 三、调度与依赖类

### Q5: 上游依赖未就绪，任务一直等待
- **报错关键字**：`当前任务等待上游调度`, `上游节点未运行`, `Dependent tasks are not ready`
- **根本原因**：
  1. 上游任务执行失败或超时，导致下游无法触发。
  2. 依赖配置错误（依赖了错误的 Project、节点名或跨周期依赖）。
  3. 上游任务未到调度时间。
- **解决方案**：
  1. 在“运维中心” -> “周期任务运维”中，查看该实例的 **DAG 图**，定位阻塞的上游节点。
  2. 去上游节点排错；若依赖配置错误，修改后重新发布。
  3. 特殊紧急情况，可进行**强制重跑**（需评估数据质量风险）。

### Q6: 任务执行超时被杀 (Timeout Killed)
- **报错关键字**：`Killed by timeout`, `Task exceeded the maximum execution time`
- **根本原因**：任务执行耗时超过了节点配置的“超时时间”。
- **解决方案**：
  1. 进入节点编辑页 -> **调度配置** -> **时间属性**，调大“超时时间”。
  2. 优化代码性能，降低执行耗时（如减少全表扫描、优化 Join 逻辑）。

## 四、资源组与网络类

### Q7: 资源组被限流 / 任务排队
- **报错关键字**：`Resource Group is busy`, `Throttling`, `Exceeded max concurrent tasks`
- **根本原因**：
  1. 当前资源组绑定的任务过多，并发达到上限。
  2. 使用的数据集成资源组并发超限。
- **解决方案**：
  1. 在“资源组列表”查看资源使用率，错峰调度，分散任务时间段。
  2. 升级/扩容资源组规格。
  3. 若使用公共资源组，建议购买独享数据集成/调度资源组。

---

## 五、外部系统/API 调用类

### Q8: API 调用超时 (如请求大模型向量库)
- **报错关键字**：`ResourceAccessException`, `SocketTimeoutException: timeout`, `I/O error on POST request`
- **根本原因**：
  1. 客户端等待响应超时。
  2. 服务端限流或计算耗时过长（如大模型文本嵌入）。
- **解决方案**：
  1. **客户端**：延长 HTTP 客户端的 Read Timeout（如 Spring WebClient 配置 `responseTimeout`）。
  2. **请求侧**：减小单次请求 Payload 体积（文本分批 Embed），增加重试机制。
  3. **网络侧**：检查是否被防火墙/NAT 设备断开了空闲长连接。

## 六、附录：
### 通用排错技巧
1. **先看摘要，再看堆栈**：日志很长时，优先看最上方的 `Error Message` 或任务状态摘要，定位核心组件（如 DataX, ODPS, Spark）。
2. **善用日志过滤**：搜索 `Exception`, `Error`, `Caused by`，顺藤摸瓜，通常最后一个 `Caused by` 才是真凶。
3. **测试连通性优先**：网络/授权报错，先做连通性测试、`ping`、`telnet` 或 `curl`。
4. **对比生产与开发**：开发环境能跑通但生产报错，大概率是环境差异（白名单、资源组、权限、参数配置）。

## 常见高频问答 (FAQ)

### 平台是做什么的？
一站式数据研发平台，用来做数据接入、SQL 开发、定时调度、任务运维、数据血缘和数据质量监控，替代手工脚本跑数据。

### 任务失败了怎么排查？
打开运维中心，找到对应失败实例，查看运行日志，根据日志报错修改 SQL 或者资源配置，修复后重跑。

### 补数据是什么，什么时候用？
补数据是重新跑历史日期的任务；适合修复历史脏数据、漏跑数据场景；在运维中心找到工作流，点击补数据，选择时间范围提交。

### `${bizdate}` 是什么？
平台内置调度变量，代表当前调度业务日期，格式 `yyyy-MM-dd`。

### 可以同时跑离线 Spark 和实时 Flink 任务吗？
支持，在开发面板选择对应类型节点即可。

### 为什么我看不到某张表？
两种情况：① 元数据采集任务还没采集到该表；② 当前账号没有这个项目 / 表的查看权限，联系管理员。

### 调试运行和提交调度有什么区别？
调试运行是手动一次性执行，只用来验证 SQL 是否正确，不会按周期自动跑；提交调度后，平台会按照 cron 周期自动生成实例定时执行。

### 版本回滚怎么用？
在任务版本列表，找到目标历史版本，点击回滚，任务会切换为该版本的脚本，建议回滚前先调试验证。

### 任务依赖是什么意思？
DAG 画布连线就是依赖，上游节点成功跑完，下游节点才会开始执行，保证数据顺序。
