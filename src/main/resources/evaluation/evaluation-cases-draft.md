| `colloquial` | 口语化 | 大白话、省略、不用文档里的术语，故意换说法 | 向量语义能力；BM25 在这类上预计吃亏 |

## 出题时我留意到的几个风险点（评估时请注意）

1. **E1 有两个正确来源**：Spark 报错篇 §1.1 与手册 Q3 都出现 `Java heap space`，标注时两个都应纳入 groundTruth，否则命中其中一个会被误判为没命中。
2. **边界声明段落可能被误召回**：两份 Spark 文档里的「边界声明」说明"不适合调参、不要召回调参知识"，但它们本身也是被入库的文本。出现在检索结果里不一定算错，要看它是否排在真答案前面。
3. **C4（Pending）有歧义**：变慢篇 §7.1 / §7.2 / §7.3 都和 Pending 相关，手册 Q5「上游依赖未就绪」也可能算相关，标注时要决定哪些算正确。
4. **没有"不该回答"的题**：这一版全部是知识库内能回答的问题，只能评估召回质量，**不能用于校准拒答阈值**。如需校准阈值，还需要另出一组库里没有答案的题（尤其是擦边的）。
5. **样本量小**：每类 10 题，分数相差几个百分点不能当结论。
6. 手册里「Q1~Q8」章节提到的 DataWorks / MaxCompute 和平台自身是否一致，我没有核对；这是文档内容问题，不影响评估，但可能影响用户体验。

## 标注方法

1. 重新入库完成后，启动应用，打开「检索评估」页面的「标注辅助」，输入问题里的关键词，会列出候选 chunk（id、章节路径、前 120 字）。
2. 对每道题，读候选内容，判断哪些 chunk 真的能回答这个问题，把 id 记下来。**一题可以对应多个 chunk。**
3. 把 id 填入评估集 JSON 的 `groundTruth`。
4. 不要用「检索系统排在前面的」当答案，那样评估等于自己给自己打分。

建议你先标 3 到 5 题跑一遍，确认页面和接口通了，再标完剩下的。
