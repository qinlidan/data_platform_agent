# 多轮对话持久化实现总结

## 实现概述

已完成 AI 助手的多轮对话持久化功能，包括用户消息、助手响应、工具调用及结果的完整记录。系统支持会话管理、历史回溯和上下文保持。

## 核心功能

### 1. 消息持久化

**三种消息角色：**
- `user`: 用户输入
- `assistant`: AI 响应（可包含 tool_calls）
- `tool`: 工具执行结果

**关键特性：**
- 消息按序号排序，保证顺序
- 异步保存，不阻塞流式响应
- JSON 格式存储工具调用
- 软删除支持

### 2. 会话管理

**会话功能：**
- 自动创建会话
- 会话列表查询
- 会话历史加载
- 会话删除（软删除）

**API 端点：**
```
GET  /api/chat/conversations/{userId}     # 获取用户所有会话
GET  /api/chat/history/{conversationId}   # 获取会话历史
DELETE /api/chat/conversations/{conversationId}  # 删除会话
```

### 3. 工具调用追踪

**实现方式：**
- `ObservableToolCallback` 装饰器模式监控工具调用
- `tool_start` / `tool_end` 事件推送
- 异步保存 tool 消息到数据库

**存储结构：**
```json
// assistant 消息中的 tool_calls
{
  "id": "call_abc123",
  "type": "function",
  "function": {
    "name": "queryDataSources",
    "arguments": "{\"status\":\"active\"}"
  }
}

// tool 消息
{
  "role": "tool",
  "content": "[{\"id\":1,\"name\":\"MySQL\"}]",
  "tool_call_id": "call_abc123"
}
```

### 4. 内存管理

**使用 Spring AI MessageChatMemoryAdvisor：**
- 基于 `conversation_id` 的隔离
- 自动加载历史消息
- 滑动窗口（默认最近 10 条）
- 支持自定义窗口大小

## 架构设计

### 核心组件

```
┌─────────────────────────────────────────────────────────────┐
│                     AiAssistantController                   │
│  - 流式响应（SSE）                                          │
│  - 事件合并（text + UI events）                            │
│  - 异步消息保存                                             │
└──────────────┬──────────────────────────────────────────────┘
               │
               ├──> MessageService (异步保存)
               │    - saveUserMessage()
               │    - saveAssistantMessage()
               │    - saveToolMessage()
               │
               ├──> ChatMemory (内存管理)
               │    - 按 conversation_id 隔离
               │    - 滑动窗口
               │
               └──> ObservableToolCallback (工具监控)
                    - 发送 tool_start/tool_end 事件
                    - 传递 tool_call_id
```

### 数据流

```
用户消息
   │
   ├─> 1. 保存到数据库（异步）
   │   2. 添加到内存
   │
   v
ChatClient 处理
   │
   ├─> 调用工具？
   │   ├─> Yes: 
   │   │    ├─> tool_start 事件
   │   │    ├─> 执行工具
   │   │    ├─> tool_end 事件
   │   │    └─> 保存 tool 消息（异步）
   │   │
   │   └─> No: 直接生成响应
   │
   v
流式返回助手响应
   │
   └─> 完成后保存（异步）
```

### 设计模式

1. **Decorator Pattern** (ObservableToolCallback)
   - 不修改原工具类
   - 添加监控能力
   - 易于扩展

2. **Strategy Pattern** (MessageChatMemoryAdvisor)
   - 可插拔的内存策略
   - 支持自定义窗口大小

3. **Observer Pattern** (Sinks.Many)
   - 事件驱动
   - 解耦生产者和消费者

## 关键实现

### 1. 流式响应中保存消息

```java
Flux<ServerSentEvent<Map<String, Object>>> textStream = chatClient.prompt()
    .system(SYSTEM_PROMPT)
    .user(message)
    .stream()
    .chatResponse()
    .mapNotNull(resp -> {
        String content = resp.getResult().getOutput().getText();
        assistantResponse.append(content);  // 累积
        return ServerSentEvent.builder()
            .event("text")
            .data(Map.of("content", content))
            .build();
    })
    .doOnComplete(() -> {
        // 流结束后异步保存完整响应
        messageService.saveAssistantMessage(
            conversationId, 
            assistantResponse.toString(), 
            null
        );
    });
```

### 2. 工具结果保存

```java
// Controller 监听 tool_end 事件
Flux<ServerSentEvent<Map<String, Object>>> uiStream = uiEventSink.asFlux()
    .map(event -> {
        if ("tool_end".equals(event.get("event"))) {
            Map<String, Object> payload = (Map) event.get("payload");
            String toolCallId = (String) payload.get("toolCallId");
            String result = (String) payload.get("result");
            
            // 异步保存
            messageService.saveToolMessage(conversationId, toolCallId, result);
        }
        return ServerSentEvent.builder()
            .event((String) event.get("event"))
            .data((Map) event.get("payload"))
            .build();
    });
```

### 3. 异步配置

```java
@Configuration
@EnableAsync
public class AsyncConfig {
    @Bean(name = "taskExecutor")
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(5);
        executor.setMaxPoolSize(10);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("async-message-");
        executor.initialize();
        return executor;
    }
}
```

## 当前限制和解决方案

### 限制 1：工具调用信息不完整

**问题：**
流式响应中 Spring AI 不直接暴露 tool_call_id

**当前方案：**
依赖 ObservableToolCallback 在 tool_end 事件中传递信息

**未来优化：**
- 研究 Spring AI 1.x ChatResponse 的完整 API
- 可能需要使用非流式 API 获取完整 tool_calls，然后手动构造流

### 限制 2：消息序号并发问题

**问题：**
高并发场景下可能出现序号冲突

**当前方案：**
数据库唯一索引 + 乐观锁

**未来优化：**
- 使用分布式序号生成器（Snowflake）
- 或使用数据库自增序列

### 限制 3：大会话性能

**问题：**
历史消息过多时加载慢

**当前方案：**
滑动窗口（默认 10 条）

**未来优化：**
- 实现智能摘要压缩
- 分段加载
- Redis 缓存热点会话
