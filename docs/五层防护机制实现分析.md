```java
// EnumValue.java - 自定义校验注解
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = EnumValueValidator.class)
public @interface EnumValue {
    String message() default "枚举值不合法";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
    Class<? extends Enum<?>> enumClass();
}

// EnumValueValidator.java - 校验器实现
public class EnumValueValidator implements ConstraintValidator<EnumValue, Enum<?>> {
    private Class<? extends Enum<?>> enumClass;
    
    @Override
    public void initialize(EnumValue annotation) {
        this.enumClass = annotation.enumClass();
    }
    
    @Override
    public boolean isValid(Enum<?> value, ConstraintValidatorContext context) {
        if (value == null) return true;
        Object[] enumValues = enumClass.getEnumConstants();
        return Arrays.asList(enumValues).contains(value);
    }
}
```

#### 2.3 第三层：自定义 ToolValidator 兜底

**问题场景**: 大模型可能传递原始类型参数（String, Long），但业务需要复杂对象。

**解决方案**: 使用 `ToolValidator` 手动转换和校验。

```java
// ToolValidator.java
@Component
@RequiredArgsConstructor
public class ToolValidator {
    
    private final Validator validator;  // JSR-303 Validator
    private final ObjectMapper objectMapper;
    
    /**
     * 将 JSON 字符串转换为对象并校验
     */
    public <T> T validateAndConvert(String json, Class<T> targetClass) {
        try {
            // 1. JSON 反序列化
            T object = objectMapper.readValue(json, targetClass);
            
            // 2. Bean Validation 校验
            Set<ConstraintViolation<T>> violations = validator.validate(object);
            if (!violations.isEmpty()) {
                String errors = violations.stream()
                    .map(v -> v.getPropertyPath() + ": " + v.getMessage())
                    .collect(Collectors.joining("; "));
                throw new IllegalArgumentException("参数校验失败: " + errors);
            }
            
            return object;
            
        } catch (JsonProcessingException e) {
            throw new IllegalArgumentException("JSON 格式错误: " + e.getMessage(), e);
        }
    }
    
    /**
     * 校验单个对象
     */
    public <T> void validate(T object) {
        Set<ConstraintViolation<T>> violations = validator.validate(object);
        if (!violations.isEmpty()) {
            String errors = violations.stream()
                .map(v -> v.getPropertyPath() + ": " + v.getMessage())
                .collect(Collectors.joining("; "));
            throw new IllegalArgumentException("参数校验失败: " + errors);
        }
    }
}
```

**使用示例（兜底方案）**:

#### 2.4 全局异常处理

统一捕获校验异常并返回友好错误信息给 AI。

```java
// GlobalExceptionHandler.java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {
    
    /**
     * 处理 Bean Validation 异常（@Valid 触发）
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleValidException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(error -> error.getField() + ": " + error.getDefaultMessage())
                .collect(Collectors.joining(", "));
        log.error("参数校验异常: {}", message);
        return Result.error(400, "参数校验失败 - " + message);
    }
    
    /**
     * 处理约束违反异常（Validator.validate() 触发）
     */
    @ExceptionHandler(ConstraintViolationException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleConstraintViolation(ConstraintViolationException e) {
        String message = e.getConstraintViolations().stream()
                .map(v -> v.getPropertyPath() + ": " + v.getMessage())
                .collect(Collectors.joining(", "));
        log.error("约束违反异常: {}", message);
        return Result.error(400, "参数校验失败 - " + message);
    }
    
    /**
     * 处理非法参数异常
     */
    @ExceptionHandler(IllegalArgumentException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleIllegalArgument(IllegalArgumentException e) {
        log.error("非法参数: {}", e.getMessage());
        return Result.error(400, e.getMessage());
    }
}
```

#### 2.5 三层校验流程总结

```
AI 调用工具
    ↓
【第一层】Spring AI JSON Schema 预校验
    ├─ 通过 → 继续
    └─ 失败 → AI 收到错误，自动修正
    ↓
【第二层】Bean Validation 运行时校验 (@Valid)
    ├─ 通过 → 继续
    └─ 失败 → MethodArgumentNotValidException → GlobalExceptionHandler
    ↓
【第三层】ToolValidator 兜底校验（可选）
    ├─ 通过 → 执行业务逻辑
    └─ 失败 → IllegalArgumentException → GlobalExceptionHandler
    ↓
返回结果给 AI
```

**优势**:
1. **分层校验**：大模型 → 框架 → 业务层，三道防线
2. **声明式配置**：用注解声明约束，代码清晰
3. **兜底保障**：即使前两层失败，第三层显式调用也能拦截
4. **友好反馈**：校验失败后，AI 收到明确错误信息，可自动修正

**结论**: ✅ 完全实现，三层校验机制确保参数合法性

```java
// ObservableToolCallback.java - 装饰器模式监控所有工具调用
@Override
public String call(String toolInput) {
    String toolName = getToolDefinition().name();
    log.info("[Tool Monitor] 开始调用工具: {}", toolName);
    emitToolStart(toolName, toolInput);
    
    long startTime = System.currentTimeMillis();
    try {
        String result = delegate.call(toolInput);
        long duration = System.currentTimeMillis() - startTime;
        log.info("[Tool Monitor] 工具调用成功: {} (耗时: {}ms)", toolName, duration);
        emitToolEnd(toolName, result, duration, null);
        return result;
    } catch (Exception e) {
        long duration = System.currentTimeMillis() - startTime;
        log.error("[Tool Monitor] 工具调用失败: {} (耗时: {}ms)", toolName, duration, e);
        emitToolEnd(toolName, null, duration, e.getMessage());
        throw e;
    }
}
```

**审计事件**:

```java
// 发送工具调用开始事件
private void emitToolStart(String toolName, String toolInput) {
    Map<String, Object> event = new HashMap<>();
    event.put("event", "tool_start");
    Map<String, Object> payload = new HashMap<>();
    payload.put("toolName", toolName);
    payload.put("input", toolInput);
    payload.put("timestamp", System.currentTimeMillis());
    event.put("payload", payload);
    
    uiEventSink.tryEmitNext(event);
}

// 发送工具调用结束事件
private void emitToolEnd(String toolName, String result, 
                         long durationMs, String errorMessage) {
    Map<String, Object> payload = new HashMap<>();
    payload.put("toolName", toolName);
    payload.put("durationMs", durationMs);
    payload.put("timestamp", System.currentTimeMillis());
    
    if (errorMessage != null) {
        payload.put("success", false);
        payload.put("error", errorMessage);
    } else {
        payload.put("success", true);
    }
    
    uiEventSink.tryEmitNext(event);
}
```

## 实现方式总结

### 1. 装饰器模式（Decorator Pattern）
```
原始工具 → ObservableToolCallback → 监控+日志
```
- 不修改原工具类
- 透明地添加监控能力
- 解耦监控逻辑和业务逻辑

### 2. 工厂方法模式
```java
ToolMonitorConfig.wrapTools(eventSink, jobTool, dsTool)
```
- 统一包装多个工具
- 简化使用方式

### 3. 事件驱动架构
```
工具调用 → SSE 事件流 → 前端实时显示
```
- 使用 Reactor Sinks 异步推送事件
- 前端通过 EventSource 接收实时更新

### 4. 分层异常处理
```
工具层捕获 → 全局异常处理器 → 统一返回格式
```
- 业务异常、参数校验异常、系统异常分类处理
- 统一的错误响应格式
