## 1. 工具查找防护

### ✅ 已实现

**实现位置**: Spring AI 框架自动处理

**机制**:
- Spring AI 使用 `@Tool` 注解扫描并注册工具
- AI 模型只能调用已注册的工具
- 未注册的工具会被框架自动拒绝

**代码示例**:
```java
// JobTool.java
@Component("jobTool")
@Slf4j
public class JobTool {
    @Tool(description = "查询作业详情...")
    public String getJobDetails(@ToolParam(description = "作业ID") Long jobId) {
        // ...
    }
}
```

**工具包装**:
```java
// ToolMonitorConfig.java
public static ToolCallback[] wrapTools(
    Sinks.Many<Map<String, Object>> eventSink, 
    Object... tools
) {
    // 将原始工具类转换为 ToolCallback 数组
    ToolCallback[] callbacks = ToolCallbacks.from(tool);
    // 包装成可观测的工具
    wrapped[index++] = new ObservableToolCallback(callback, eventSink);
}
```

**结论**: ✅ 完全实现，未知工具会被框架拒绝

## 2. JSON Schema 校验

### ⚠️ 部分实现

**当前状态**:
- ✅ 使用 `@Valid` 注解进行 JSR-303 参数校验
- ✅ 使用自定义校验注解 `@EnumValue`
- ❌ 未使用 JSON Schema 显式定义工具参数格式
- ❌ 参数校验失败后，模型无法自动修正

**已实现的参数校验**:

**全局异常处理**:
```java
// GlobalExceptionHandler.java
@ExceptionHandler(MethodArgumentNotValidException.class)
```

## 3. 权限门（二次确认）

### ✅ 已实现

**实现位置**: `JobTool.java`

**高危操作**:
1. **删除作业** - 需要二次确认
2. **发布作业** - 需要二次确认

**实现机制**:

```java
// 删除作业需要确认
@Tool(description = "删除作业。删除指定的作业（需要用户二次确认）...")
public String deleteJob(
    @ToolParam(description = "jobId") Long jobId,
    @ToolParam(description = "confirmed") Boolean confirmed
) {
    if (confirmed == null || !confirmed) {
        return String.format(
            "⚠️ 确认删除作业 ID=%d（%s/%s）吗？此操作不可恢复！请回复\"确认\"继续。",
            job.getId(), job.getJobName(), job.getJobCnName()
        );
    }
    jobService.delete(job.getId());
    return String.format("作业 ID=%d 已删除", jobId);
}
```

```java
// 发布作业需要确认
@Tool(description = "发布作业。将作业的指定版本发布到生产环境（需要用户二次确认）...")
public String publishJob(
    @ToolParam(description = "jobId") Long jobId,
    @ToolParam(description = "version") Integer version,
    @ToolParam(description = "confirmed") Boolean confirmed
) {
    if (confirmed == null || !confirmed) {
        return String.format(
            "⚠️ 确认发布作业 ID=%d（%s/%s）的版本 %d 吗？发布后将影响生产环境！请回复\"确认\"继续。",
            job.getId(), job.getJobName(), job.getJobCnName(), version
        );
    }
    jobService.publish(job.getId(), version);
    return String.format("作业 ID=%d 的版本 %d 已发布！", jobId, version);
}
```

**交互流程**:
1. AI 首次调用 `deleteJob(jobId=1, confirmed=false)`
2. 工具返回: "⚠️ 确认删除作业 ID=1 吗？"
3. 用户回复: "确认"
4. AI 再次调用 `deleteJob(jobId=1, confirmed=true)`
5. 工具执行删除并返回成功消息

**结论**: ✅ 完全实现，模型无法绕过二次确认

## 4. 执行 + 重试

### ❌ 未实现自动重试

**当前状态**:
- ✅ 有异常处理机制
- ✅ 有日志记录
- ❌ 没有自动重试逻辑
- ❌ 没有区分只读/写操作的重试策略

**异常处理**:

```java
// JobTool.java - 所有工具方法都有异常捕获
@Tool(description = "...")
public String getJobDetails(@ToolParam(description = "作业ID") Long jobId) {
    try {
        Job job = jobService.getById(jobId);
        return formatJobDetails(job);
    } catch (Exception e) {
        log.error("[AI Tool] getJobDetails 失败", e);
        return "查询失败：" + e.getMessage();
    }
}
```

**全局异常处理**:

```java
// GlobalExceptionHandler.java
@ExceptionHandler(BusinessException.class)
public Result<Void> handleBusinessException(BusinessException e) {
    log.error("业务异常: {}", e.getMessage(), e);
    return Result.error(e.getCode(), e.getMessage());
}

@ExceptionHandler(SQLException.class)
public Result<Void> handleSQLException(SQLException e) {
    log.error("数据库异常: {}", e.getMessage(), e);
    return Result.error(500, "数据库操作失败");
}
```

**建议改进**:
```java
// 使用 Spring Retry 实现自动重试
@Retryable(
    value = {SQLException.class, DataAccessException.class},
    maxAttempts = 3,
    backoff = @Backoff(delay = 1000, multiplier = 2)
)
@Tool(description = "查询作业详情（只读操作，支持重试）")
public String getJobDetails(@ToolParam(description = "作业ID") Long jobId) {
    // 只读操作，可以安全重试
    return jobService.getById(jobId);
}

// 写操作不重试
@Tool(description = "创建作业（写操作，不重试）")
public String createJob(...) {
    // 写操作，不能重试，避免重复创建
    return jobService.create(request);
}
```

**结论**: ❌ 缺少自动重试机制，需要引入 Spring Retry

### 5.2 审计（日志记录）

**✅ 已实现** - 工具调用监控:

```java
// ObservableToolCallback.java - 装饰器模式监控所有工具调用
@Override
public String call(String toolInput) {
    String toolName = getToolDefinition().name();
    log.info("[Tool Monitor] 开始调用工具: {}", toolName);
    emitToolStart(toolName, toolInput);
    
    long startTime = System.currentTimeMillis();
    try {
        String result = delegate.call(toolInput);
        long duration = System.currentTimeMillis() - startTime;
        log.info("[Tool Monitor] 工具调用成功: {} (耗时: {}ms)", toolName, duration);
        emitToolEnd(toolName, result, duration, null);
        return result;
    } catch (Exception e) {
        long duration = System.currentTimeMillis() - startTime;
        log.error("[Tool Monitor] 工具调用失败: {} (耗时: {}ms)", toolName, duration, e);
        emitToolEnd(toolName, null, duration, e.getMessage());
        throw e;
    }
}
```

**审计事件**:

```java
// 发送工具调用开始事件
private void emitToolStart(String toolName, String toolInput) {
    Map<String, Object> event = new HashMap<>();
    event.put("event", "tool_start");
    Map<String, Object> payload = new HashMap<>();
    payload.put("toolName", toolName);
    payload.put("input", toolInput);
    payload.put("timestamp", System.currentTimeMillis());
    event.put("payload", payload);
    
    uiEventSink.tryEmitNext(event);
}

// 发送工具调用结束事件
private void emitToolEnd(String toolName, String result, 
                         long durationMs, String errorMessage) {
    Map<String, Object> payload = new HashMap<>();
    payload.put("toolName", toolName);
    payload.put("durationMs", durationMs);
    payload.put("timestamp", System.currentTimeMillis());
    
    if (errorMessage != null) {
        payload.put("success", false);
        payload.put("error", errorMessage);
    } else {
        payload.put("success", true);
    }
    
    uiEventSink.tryEmitNext(event);
}
```

## 实现方式总结

### 1. 装饰器模式（Decorator Pattern）
```
原始工具 → ObservableToolCallback → 监控+日志
```
- 不修改原工具类
- 透明地添加监控能力
- 解耦监控逻辑和业务逻辑

### 2. 工厂方法模式
```java
ToolMonitorConfig.wrapTools(eventSink, jobTool, dsTool)
```
- 统一包装多个工具
- 简化使用方式

### 3. 事件驱动架构
```
工具调用 → SSE 事件流 → 前端实时显示
```
- 使用 Reactor Sinks 异步推送事件
- 前端通过 EventSource 接收实时更新

### 4. 分层异常处理
```
工具层捕获 → 全局异常处理器 → 统一返回格式
```
- 业务异常、参数校验异常、系统异常分类处理
- 统一的错误响应格式

## 改进建议

### 高优先级
1. **引入 Spring Retry**
   - 为只读操作添加自动重试
   - 记录重试次数
   - 配置指数退避策略

2. **添加 JSON Schema**
   - 为复杂工具定义 Schema
   - 让 AI 提前知道参数约束
   - 减少参数错误

### 中优先级
3. **持久化审计日志**
   - 将工具调用记录写入数据库
   - 支持审计查询和统计
   - 便于故障排查

4. **工具调用限流**
   - 防止 AI 频繁调用
   - 保护后端服务

### 低优先级
5. **工具调用可视化**
   - 前端展示调用链路
   - 调用统计和报表
