# 多轮对话持久化测试指南

## 功能概述

系统已实现完整的多轮对话持久化功能，包括：
- 用户消息保存
- 助手响应保存
- 工具调用和结果保存
- 会话历史管理

## 数据库表结构

### conversations 表
```sql
CREATE TABLE conversations (
    conversation_id VARCHAR(50) PRIMARY KEY COMMENT '会话ID',
    user_id VARCHAR(50) COMMENT '用户ID',
    title VARCHAR(200) COMMENT '会话标题',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at TIMESTAMP NULL COMMENT '软删除时间'
);
```

### messages 表
```sql
CREATE TABLE messages (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    conversation_id VARCHAR(50) NOT NULL COMMENT '会话ID',
    role ENUM('user', 'assistant', 'tool') NOT NULL COMMENT '角色',
    content TEXT COMMENT '消息内容',
    tool_calls JSON COMMENT '工具调用列表（仅 assistant 角色）',
    tool_call_id VARCHAR(50) COMMENT '工具调用ID（仅 tool 角色）',
    sequence_number INT NOT NULL COMMENT '消息序号',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_conversation_sequence (conversation_id, sequence_number)
);
```

## 测试场景

### 1. 基础对话测试

**测试步骤：**

1. 创建新会话：
```bash
curl -X POST http://localhost:8080/api/chat/send \
  -H "Content-Type: application/json" \
  -d '{
    "message": "你好，请介绍一下你自己",
    "conversationId": "test-conv-001"
  }'
```

2. 检查消息是否保存：
```sql
-- 查看会话
SELECT * FROM conversations WHERE conversation_id = 'test-conv-001';

-- 查看消息历史
SELECT 
    id, 
    role, 
    LEFT(content, 50) as content_preview, 
    sequence_number,
    created_at
FROM messages 
WHERE conversation_id = 'test-conv-001'
ORDER BY sequence_number;
```

**预期结果：**
- `conversations` 表应有一条记录
- `messages` 表应有两条记录：
  - sequence_number=1: role='user', content='你好，请介绍一下你自己'
  - sequence_number=2: role='assistant', content='AI助手的自我介绍...'

### 2. 工具调用测试

**测试步骤：**

1. 发送需要调用工具的消息：
```bash
curl -X POST http://localhost:8080/api/chat/send \
  -H "Content-Type: application/json" \
  -d '{
    "message": "查询所有的数据源",
    "conversationId": "test-conv-002"
  }'
```

2. 检查工具调用记录：
```sql
-- 查看助手消息（包含工具调用）
SELECT 
    id,
    role,
    LEFT(content, 30) as content,
    tool_calls,
    sequence_number
FROM messages 
WHERE conversation_id = 'test-conv-002' 
  AND role = 'assistant'
  AND tool_calls IS NOT NULL;

-- 查看工具结果
SELECT 
    id,
    role,
    tool_call_id,
    LEFT(content, 50) as result,
    sequence_number
FROM messages 
WHERE conversation_id = 'test-conv-002' 
  AND role = 'tool';
```

**预期结果：**
- assistant 消息包含 tool_calls JSON
- tool 消息包含 tool_call_id 和结果

**测试步骤：**

3. 第三轮：修改数据源
```bash
curl -X POST http://localhost:8080/api/chat/send \
  -H "Content-Type: application/json" \
  -d '{
    "message": "把这个数据源的名称改为test_ds_new",
    "conversationId": "test-conv-003"
```

4. 检查对话历史：
```sql
SELECT 
    sequence_number,
    role,
    CASE 
        WHEN role = 'user' THEN content
        WHEN role = 'assistant' THEN LEFT(content, 50)
        WHEN role = 'tool' THEN CONCAT('Tool:', tool_call_id)
    END as message_info,
    created_at
FROM messages 
WHERE conversation_id = 'test-conv-003'
ORDER BY sequence_number;
```

**预期结果：**
- 消息按序号排列
- 能够看到完整的对话流程
- AI 能够理解上下文（"刚才创建的数据源"）

## 常见问题

### Q1: 消息没有保存到数据库？

**检查点：**
1. 查看应用日志，确认 `MessageService.saveUserMessage()` 和 `saveAssistantMessage()` 被调用
2. 检查数据库连接配置
3. 确认异步任务配置生效：
```bash
# 查看日志中是否有 "async-message-" 线程名前缀
grep "async-message-" logs/data-platform.log
```

### Q2: 工具调用没有记录？

**检查点：**
1. 确认 `ObservableToolCallback` 已正确包装工具
2. 检查 `tool_end` 事件是否触发：
```bash
# 查看日志
grep "Tool Monitor" logs/data-platform.log
```
3. 确认 `saveToolMessage()` 被调用

### Q3: 历史对话无法加载？

**检查点：**
1. 确认 `MessageChatMemoryAdvisor` 配置正确
2. 检查 conversation_id 是否一致
3. 查看内存中的对话历史：
```java
// 在 Controller 中添加调试日志
log.debug("Chat memory size: {}", chatMemory.get(conversationId, Integer.MAX_VALUE).size());
```

## 性能考虑

### 1. 异步保存

所有消息保存操作都是异步执行，不阻塞主流：
```java
@Async("taskExecutor")
public void saveUserMessage(String conversationId, String content) {
    // 异步执行
}
```

### 2. 索引优化

确保以下索引存在：
```sql
-- 会话ID + 序号复合索引
CREATE INDEX idx_conversation_sequence ON messages(conversation_id, sequence_number);

-- 会话ID索引（用于删除）
CREATE INDEX idx_conversation_id ON messages(conversation_id);
```

### 3. 批量查询

加载历史消息时限制数量：
```java
// 默认加载最近 50 条消息
messageService.getConversationHistory(conversationId, 50);
```
